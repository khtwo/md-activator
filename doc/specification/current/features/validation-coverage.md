# Validation Coverage

_[← Application Features index](../application-features.md)._ A cross-cutting summary of what the committed test suite currently covers across all feature domains.

## Validation Coverage
Current committed tests cover:
- Viewer page shell response.
- Default render endpoint behavior.
- In-process render and folder-metadata caching: cached HTML/link reuse for unchanged files, mtime-triggered refresh, low-usage-then-oldest-access eviction, idle-entry cleanup, write-back invalidation, and folder-metadata keying, TTL freshness, eviction, and root-change clearing.
- YAML (`.yml`/`.yaml`) collapsible indentation-tree rendering: branch/leaf detection, default-expanded toggles, blank-line preservation, HTML escaping, empty-file state, the `/api/render` and direct-URL paths, and in-app linkification of YAML path references.
- JSON (`.json`/`.jsonl`) collapsible pretty-printed value-tree rendering: object/array branch and scalar/empty-container leaf detection, default-expanded toggles, re-indentation of minified input, sibling comma placement, HTML escaping, invalid-JSON error state, empty-file state, JSON Lines per-line records, the `/api/render` and direct-URL paths, and in-app linkification of JSON path references.
- Front-matter rendering: leading `---` ... `---` block detection (and non-detection for missing leading/closing delimiters and empty blocks), two-column key/value table emission with reused table styling, first-colon key/value split, nested-block tables, HTML escaping, in-place blanking that preserves body line numbers for checkbox write-back, and the unchanged `/api/render` shape.
- Checkbox rendering.
- Local and internet image rendering.
- Relative link resolution with `base`.
- Inline markdown path linkification.
- Mermaid block preparation for fenced and raw diagram blocks.
- Diagram canvas Ctrl+wheel zoom-to-cursor with scale clamping, empty-area drag-to-pan, double-click-to-reset, and session-persistent view-only zoom/pan state for both Mermaid and maxGraph canvases, including maxGraph pan/node-drag disambiguation by pointer-down target.
- maxGraph-compatible XML block preparation and browser rendering for fenced `maxgraph`, `mxgraph`, `maxgraphcolor`, and `maxgraphcolorall` blocks, including normal/color/color-all style-mode gating for `fillColor`, `strokeColor`, `fontColor`, `labelBackgroundColor`, `fontSize`, and `rounded`, independent `startArrow`/`endArrow` marker support for `none`, `classic`, `classicThin`, `block`, `blockThin`, `open`, `openThin`, `oval`, `diamond`, and `diamondThin`, local SVG-only maxGraph rendering without upstream `@maxgraph/core` dependency, draggable entity-box changed-position preview re-render without saving, draggable entity-box location write-back on drop, inline multiline entity-title textarea editing with width-based title wrapping, rendered line breaks, and blur-triggered title write-back, inline 3-line edge-title textarea editing with rendered line breaks and blur-triggered title write-back, 50-step Ctrl+Z/Ctrl+Y undo/redo history, orthogonal edge style rendering, ignored imported fixed link positions, perpendicular orthogonal edge approach, shifted same-side connection points across incoming and outgoing links with even two-arrow-width spacing and side-middle grouping when side span permits, same-side port order optimization, shifted overlapping orthogonal route lanes with at least 1.5 arrow widths of visual clearance between shifted parallel connector segments when a route can provide that separation, node-avoiding orthogonal routes, avoidable link-overlap reduction, avoidable line-crossing reduction, direct straight-route preference for overlapping nodes, arrowhead endpoint clearance, side-pair selection, shifted attachment points, center-side tie breaking, edge label placement near the longest rendered segment, and diagram bounds that include routed connector segments and final edge-label text blocks.
- Same-folder markdown file and folder listing.
- Review-prioritized new-file notifications: unchecked `[ ] Confirm` / `[ ] **Confirm** ` / `[ ] [Confirm]` marker detection (case-insensitive) and non-detection for checked boxes, mid-sentence prose, and markers inside fenced code blocks (backtick or tilde fences, including info-string and unclosed fences, while a real marker outside the fence — or after a closed fence — still counts), the `priority_filter` tagging in-window files with `needsReview` and ordering them first while preserving recency within each group, `/api/new-files` returning the combined ordered list with per-item `needsReview` and `attentionCount` (= reviewCount + unviewed non-review) plus the existing paging/detect/no-change/self-clearing behavior, the five-control toolbar grid keeping one row, and the single notification bell (one list, yellow-circle marker on review rows, `attentionCount` badge) index/app.js/controller wiring.
- New-file dropdown row layout: each row rendering `<filename> (<parent-folder>/)` with the parent folder derived from the content-root-relative path and shown with a trailing slash (root-level files showing just the filename, no empty parentheses), the folder span styled non-bold and smaller so it stays secondary even when an unviewed filename is bold, the combined string clamped to 2 lines, and the row's `:title` exposing the full relative path (relative path + filename) as hover text; `newFileParentDir` deriving the parent folder (`''` for a root-level file) verified via the Node probe.
- Per-file last-view timestamp resurfacing: the registry storing each viewed file's last-view timestamp (`{"viewed": {"<abs>": <epoch>}}`), a file going `viewed=false` (bold, `unviewedCount`) again once its activity time passes its recorded view, a fresh open recording the current time to clear it, the legacy flat-list format read as viewed-as-of-load (no mass-bold on upgrade) then resurfacing after a rewrite + later modification, and the end-to-end render→`os.utime`→detect path flipping a previously-viewed file back to unviewed.
- Mark-all-viewed notification action: `NewFilesService.mark_all_viewed` flipping every file in the cached list (across all pages) to viewed and `ViewedRegistry.mark_all_viewed` batching a single idempotent registry write, `POST /api/new-files/mark-all-viewed` marking all files across pages (`unviewedCount` to `0`, every item `viewed`) while review files keep their `reviewCount`/`attentionCount`, and the borderless `viewer-new-files-mark-all` footer button (shown whenever the list has files) wired to the controller's `markAllNewFilesViewed`, which POSTs then refreshes so the badge clears and rows read viewed.
- New-file-change desktop notification: the detector (`detect()`) raising a throttled desktop notification for files created/changed after the session baseline — first-scan baseline suppression (no backlog notification), the `created` vs `changed` verb by activity-epoch diff, the single-file `"<path> is created/changed"` body versus the newest-named `"… and N more file(s) changed"` batch body, the one-per-3-seconds coalescing throttle (advancing injected clock), and the opt-in `notifier=None` default staying side-effect-free; plus `notify_change` dispatching to the Windows (`win11toast`) / macOS (`osascript`) / Linux (`notify-send`) backend by platform and falling back to a console line on an unknown platform or a raising backend, `_osa_quote` escaping, and `schedule_change_notification` running on a joinable daemon thread.
- Browser file/folder dropdown collapse/expand: visible-option filtering for single, nested, and sibling folder collapse, expandable-folder detection, and the non-navigating toggle wiring.
- Browser file/folder dropdown current-folder header: a non-clickable header pinned above the option list (Quasar QSelect `before-options`) showing the current folder's content-root-relative path with a trailing `/` (content root shown as `/`) at the same font and size as the option rows (`font-size: inherit`), fed by the `createFileDropdownCollapse` `currentFolderLabel` computed, and the `viewerCurrentFolder` helper deriving that folder from the open file's path (parent folder) or an empty folder's own path — reusing `VIEWER_LINK_SUFFIXES` to tell a file from a folder — verified via the Node probe.
- In-preview content search: case-insensitive non-overlapping match finding, whole-string run splitting, both-direction wrap-around match navigation, the current/total counter label, embedded-preview gating with `Ctrl+F` binding, shared-class prose and SVG highlighting, single-init wiring inside setup, search asset wiring into template and manifest, and box/hit/dark-theme styles.
- Error banner behavior: clearing on a different-page render, persistence of sticky write-back errors across same-page auto-refresh, and clearing a transient fetch/refresh error (`Failed to fetch`) once a later render or file-option refresh succeeds while leaving a sticky error in place.
- Folder selection rendering of immediate readme, first immediate markdown file in the folder, or no-markdown message.
- Content-root escape rejection.
- Release packaging payload selection and unsafe version rejection.
- VS Code extension manifest, staging, and runtime helper behavior.
- Local VSIX packaging behavior.
- Single-file (`--open`) ready announcement: Windows toast success (no console line) and toast-failure console fallback, and on non-Windows opening the announced URL in the default browser, with the console fallback when no browser can be launched (`open` returns false) or the open call raises.
- Cross-platform test execution: the `.bat` launcher/packaging tests (`test_start_bat`, `test_release_bat`, `test_vsix_package_bat`, `test_release_version_bat`) are gated to Windows (`sys.platform == "win32"`) so they skip rather than error on macOS/Linux, while the plain-text assertions over `.bat` script contents stay cross-platform.

Browser URL/history and dropdown interaction are specified and manually verifiable; dedicated browser automation is not currently committed.
